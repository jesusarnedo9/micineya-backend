# Próximo release: recomendaciones renovables

Primer bloque implementado del release orientado a Google Play. El bloque de fotos, cambio de contraseña y eliminación de cuenta se documenta en [cuentas y perfil](1.1-cuentas-perfil.md). La verificación de correo, recuperación de contraseña y funciones sociales siguen pendientes.

## Comportamiento

- **Otras 10** solicita un nuevo lote y sincroniza Para vos con la ruleta. El lote anterior se conserva si la petición falla.
- Al iniciar una nueva sesión de la app se consultan recomendaciones. Al volver desde segundo plano, se renuevan si pasaron 24 horas desde la última carga correcta.
- El backend guarda las últimas 50 películas recomendadas por cuenta y prioriza otras. Consulta hasta 10 páginas del catálogo cuando las primeras no ofrecen suficientes alternativas.
- Renovar excluye expresamente los IDs del lote actual. Las vistas y las descartadas también quedan excluidas, incluso si faltan títulos para completar diez.
- Si no hay suficientes opciones nuevas, pueden volver recomendaciones anteriores al lote actual. Se mantienen los filtros de plataformas, géneros y disponibilidad por suscripción en Argentina.
- **No me interesa** oculta la película durante 30 días. No elimina guardados ni modifica géneros. El aviso permite deshacer el último descarte o cerrar el aviso.
- Al agotar el lote entre vistas y descartadas, se consulta otro automáticamente.
- Si hay menos de diez opciones, la pantalla lo indica y permite ir al perfil para ampliar los gustos.

## API

`POST /api/peliculas/recomendadas/renovar`

```json
{ "actualesIds": [550, 603] }
```

Acepta de cero a diez IDs positivos y devuelve el mismo formato `results` del endpoint de recomendaciones existente.

`PUT /api/peliculas/descartadas/{tmdbId}` y `DELETE /api/peliculas/descartadas/{tmdbId}` devuelven 204. Usan exclusivamente la cuenta autenticada; no aceptan un ID de usuario del cliente. Repetir el descarte actualiza su vencimiento y repetir su eliminación no falla.

## Despliegue

1. Desplegar primero el backend. La configuración existente `spring.jpa.hibernate.ddl-auto=update` crea las tablas adicionales `usuario_recomendacion_reciente` y `usuario_pelicula_descartada`; no es necesario borrar datos ni cambiar variables de entorno para este bloque.
2. Probar el frontend con ese backend. Para distribuir los cambios a quienes ya tienen la aplicación instalada, generar una nueva compilación de Android.
3. Antes de publicación en Google Play queda pendiente incorporar migraciones versionadas de base de datos y los restantes requisitos del release.

## Validación breve en el teléfono

1. En Para vos, pedir Otras 10 y comprobar que la ruleta toma títulos del nuevo lote.
2. Descartar una película desde la mitad del feed: debe desaparecer y continuar con la siguiente. Deshacer debe permitir recuperarla.
3. Volver a descartar, cerrar la app y abrirla: la exclusión debe persistir. La lista de guardadas no debe cambiar.
4. Marcar o descartar todas las opciones: debe aparecer otro lote, o un estado vacío útil si se agotó el catálogo.
5. Sin conexión, pedir Otras 10: debe aparecer un error y conservarse el lote anterior.

Las pruebas automatizadas enfocadas son `TmdbServiceTests` y `RecomendacionesUsuarioTests`; cubren exclusiones, ampliación del catálogo, afinidad, trailers, límite de sagas, persistencia, aislamiento entre cuentas, deshacer, vencimiento y límite del historial.
